Hindsight 0.8.6 builds on [0.8.5](/blog/2026/07/21/version-0-8-5) with a focus on **control, visibility, and reliability under load**: tune how hard the model thinks **per operation**, browse memory by **entity and tag** in the control plane, and find out **at write time** when a document produced no memories. It also lands a large batch of **worker, graph-maintenance, and platform fixes**. **Self-managed deployments should upgrade** — several of these fixes protect background work from stalling or duplicating.

- [**Per-Operation Model Control**](#per-operation-model-control): Set reasoning effort separately for retain, reflect, and consolidation.

- [**Workers That Don't Get Stuck**](#workers-that-dont-get-stuck): Wedged retains, reserved slots, queue races, and backpressure.

## Per-Operation Model Control

Reasoning models are not equally useful at every stage of a memory pipeline. Extraction benefits from care; a short reflect answer usually does not, and paying for reasoning tokens there is pure latency and cost.

0.8.6 lets you set the reasoning effort **per operation** instead of once for the whole deployment, with `HINDSIGHT_API_RETAIN_LLM_REASONING_EFFORT`, `HINDSIGHT_API_REFLECT_LLM_REASONING_EFFORT`, and `HINDSIGHT_API_CONSOLIDATION_LLM_REASONING_EFFORT`. Anything you don't set keeps following the global `HINDSIGHT_API_LLM_REASONING_EFFORT`, so existing deployments behave exactly as before.

Two related fixes make the setting trustworthy: reasoning effort is now sent consistently on tool-calling requests as well as plain completions, and it propagates correctly to Codex.

Alongside it, more of the pipeline became tunable: embedding thresholds are now configurable, and `store_document_text` can be overridden per bank so you can keep raw document text out of specific banks.

## See What Your Memory Contains

Memory is only as useful as your ability to inspect it. This release makes browsing a bank far more direct:

- **Entity timeline.** Pick an entity and see everything Hindsight knows about it, in order — plus a matching API filter that lists memories by linked entity.
- **Tag and document filters.** Documents can be filtered by tag in the control plane, and the filter chips across the UI now behave and look the same everywhere.
- **Zero-fact documents are reported.** When a document is retained but yields no facts, that is now surfaced at write time instead of looking like a silent success — the single most common source of "I stored it, why can't I recall it?".
- **API version in the sidebar.** The control plane shows which API version it is talking to.

The audit-log and observations tabs now follow the resolved per-bank configuration rather than the global flag, so a bank with audit logging enabled shows its audit tab even when the server default is off. Dark mode also renders correctly again throughout the control plane.

## Workers That Don't Get Stuck

The theme of this release's reliability work is background jobs that stop making progress but keep holding resources:

- **Wedged retains no longer hold worker slots forever.** A retain that stops progressing is now bounded, released, and retried instead of permanently consuming a slot.
- **Per-type slots say what they do.** The per-operation worker slot settings are now `HINDSIGHT_API_WORKER_<TYPE>_RESERVED_SLOTS`: they reserve a guaranteed _minimum_ for that operation type, they never cap it. The old `*_MAX_SLOTS` names still work and log a deprecation warning, so nothing changes until you rename them.
- **Graph maintenance no longer drops work.** A race between queuing maintenance and workers draining the queue could lose a re-queue signal; queuing and draining are now serialized.
- **Batch retain recovers.** Failed batch retains can be retried — children are re-queued and the parent revived — and parents stranded by a hard kill are reconciled on startup.
- **Retries are idempotent.** A caller-supplied operation id makes a retried async retain safe to send twice.
- **Embedding backpressure is respected.** Remote embedding and reranking calls retry on HTTP 429 with jittered backoff instead of failing the request outright.
- **A stalled health check explains itself.** When `/health` stops responding, Hindsight now tells you whether the event loop is blocked or the database pool is exhausted — the difference between a restart that helps and a restart that thrashes.
- **Graph and recall are faster.** Redundant graph seeding and identifier scans were eliminated on large banks.

## Reflect You Can Steer

- **Apply directives across all scopes.** A new `apply_all_directives` option lets a reflect call use every directive in the bank, bypassing tag scoping when you want the full instruction set.
- **Failures are honest.** When a provider returns no usable tool call, reflect now fails clearly instead of salvaging text that leaked around the tool contract — a silent quality trap on providers that quietly drop tools.
- **Correct mental-model scoping.** An empty scope is now applied exactly, rather than widening to everything.
- **Claude Code as a provider.** Reflect tool calls work, and the configured model is honored.

## Runs Where You Run

- **Oracle 23ai.** Several dialect issues are fixed, including full-text handling during consolidation, audit-log writes, and updating a bank's mission.
- **AWS Bedrock.** Consolidation no longer emits a schema field Bedrock rejects, which previously broke consolidation entirely on Bedrock.
- **Apple Silicon.** Local embedding and reranking models now default to CPU, avoiding a memory leak that could grow to tens of gigabytes on an idle Mac.
- **Kubernetes.** Worker pods override the API port explicitly, so service discovery can no longer break the worker's own port.
- **Local model servers.** Bare LM Studio and Ollama base URLs are normalized, so a URL without a path just works.
- **Python 3.14** is supported.
- **Importing Hindsight as a library** no longer applies `.env` side effects to your process environment.

Other notable changes:

- **Curation keeps its links.** Causal links survive edit, invalidate, and restore, and edited or restored memories are re-queued for relinking.
- **Whole-bank import.** Consolidation lifecycle state is preserved on import, so an imported bank isn't immediately re-consolidated into duplicates.
- **Append-only history.** Re-ingesting a long, oversized document is recognized as an append again instead of re-extracting from scratch.
- **Backups.** Restore handles schema-compatibility differences.
- **Extensions.** Extensions can declare bank-scoped tables that are provisioned automatically.
- **Embedded engine.** Memory units can be deleted in bulk and listed by ingest age, for maintenance code that drives the engine directly.
- **Clients.** The TypeScript client supports custom headers, and the Python client exposes the mental-model query controls and the async retain operation id.
- **CLI.** HTTP 400 details are preserved instead of being flattened into a generic error.
- **Temporal parsing.** Russian temporal period rules were added.
